# Бизнес-логика проекта excel-telegram-bot-starter

**Последнее обновление:** 2026-02-01

Этот документ описывает полную бизнес-логику системы, состоящей из трёх компонентов:
1. **Owner Bot** (@tophitboss_bot) - бот владельца магазина
2. **Shop Bot** (@mahoorka_bot) - бот магазина для покупателей
3. **Сайт** (sitemahorkaproject) - веб-витрина магазина

---

## 1. Архитектура системы

```
+------------------+     +------------------+     +------------------+
|                  |     |                  |     |                  |
|   Owner Bot      |     |   Shop Bot       |     |   Website        |
|   @tophitboss    |     |   @agrosna1b     |     |   (React SPA)    |
|                  |     |                  |     |                  |
+--------+---------+     +--------+---------+     +--------+---------+
         |                        |                        |
         |                        |                        |
         v                        v                        v
+--------+------------------------+------------------------+---------+
|                                                                    |
|                        Google Sheets                               |
|       (Склад, Заказы, Списание, Leads, MetricsDaily, etc.)        |
|                                                                    |
+--------------------------------------------------------------------+
         |
         v
+--------+---------+
|                  |
|   Google Drive   |
|   (Фото товаров) |

+------------------+
```

### 1.1 Общие зависимости

- **Google Sheets** - единый источник правды для каталога, настроек, заказов и CRM
- **Google Drive** - хранилище фотографий товаров
- **SQLite** - локальное хранилище для корзин и сессий (Shop Bot)
- **Telegram Bot API** - интерфейс для ботов
- **OpenAI API** - AI-менеджер (опционально)
- **CDEK API** - интеграция доставки (опционально)

## 2. Owner Bot (@tophitboss_bot)

**Путь:** `/owner_bot/`
**Назначение:** Управление складом, товарами, CRM и мониторинг системы

### 2.1 Безопасность

Бот доступен только авторизованным владельцам:
- Список ID указывается в `OWNER_TELEGRAM_IDS`
- `WhitelistMiddleware` блокирует неавторизованных пользователей
- Подтверждение опасных операций через `ConfirmAction` с TTL

### 2.2 Главное меню

```
+------------------------------------------+
| 📦 Приход товара  |  📊 Склад            |
+------------------------------------------+
| 🔍 Найти товар    |  📋 Заказы сегодня   |
+------------------------------------------+
| 📊 CRM            |  🔧 Статус           |
+------------------------------------------+
```

### 2.3 Функции Owner Bot

#### 2.3.1 Приход товара (Intake Flow)

**FSM состояния:** `IntakeState`
- `waiting_for_input` - ожидание быстрой строки или названия
- `waiting_for_name` - ввод названия
- `waiting_for_price` - ввод цены
- `waiting_for_quantity` - ввод количества
- `waiting_for_match_decision` - выбор существующего товара или создание нового
- `waiting_for_photo_decision` - решение о фото
- `waiting_for_photo` - загрузка фото
- `photo_review` - проверка качества фото
- `preview_confirm` - подтверждение прихода
- `retry_sheets_write` - повтор при ошибке записи

**Сценарий:**
1. Владелец нажимает "📦 Приход товара"
2. Вводит данные одним сообщением: `Название Цена Количество`
   - Пример: `Махорка СССР 500 10`
3. Система парсит строку с оценкой уверенности (HIGH/LOW)
4. Поиск похожих товаров в базе
5. Выбор: обновить существующий или создать новый
6. Решение о фото: добавить/заменить/пропустить
7. Если фото загружено:
   - Анализ качества (размер, резкость, яркость)
   - Опции: принять, улучшить, переснять
8. Превью и подтверждение
9. Запись в Google Sheets + загрузка фото в Drive

**Проверки качества фото:**
- Минимальный размер: 800px (настраивается)
- Резкость: threshold 100.0
- Яркость: 40-220

#### 2.3.2 Поиск товара

**FSM состояния:** `ProductState`
- `searching` - ожидание запроса
- `viewing` - просмотр карточки

**Функции карточки товара:**
- 📦 Приход - быстрое добавление прихода
- ➖ Списать - уменьшить остаток с причиной
- 🧮 Корректировка - установить фактический остаток
- 📷 Фото - замена фотографии
- 🗑️ Архив - деактивировать товар

#### 2.3.3 Просмотр склада (📊 Склад)

**Функции:**
- Постраничный список всех товаров (8 на страницу)
- Сортировка: активные товары вверху, далее по названию
- Статистика: количество активных, общий остаток
- Быстрый переход к карточке любого товара

#### 2.3.4 Операции с товарами

**FSM состояния:** `StockOperationState`
- `writeoff_qty` - ввод количества для списания
- `writeoff_reason` - выбор причины списания
- `correction_qty` - ввод фактического остатка
- `correction_reason` - выбор причины корректировки
- `archive_menu` - выбор режима архивации

При выборе товара доступны операции:

| Операция | Описание |
|----------|----------|
| 📦 Приход | Добавить количество к остатку |
| ➖ Списать | Уменьшить остаток (порча, подарок, пересорт) |
| 🧮 Корректировка | Установить фактический остаток |
| 📷 Фото | Заменить фотографию |
| 🗑️ Архив | Деактивировать (скрыть из каталога) |

**Причины списания:**
- 🗑️ Порча — испорченный товар
- 🎁 Подарок — отдан в подарок
- 🔄 Пересорт — пересортировка
- 📝 Другое — своя причина

**Причины корректировки:**
- 📋 Инвентаризация — по результатам пересчёта
- 🔄 Пересорт — пересортировка товаров
- ⚠️ Ошибки учёта — исправление ошибок
- 📝 Другое — своя причина

**Режимы архивации:**
- **Архивировать** — скрыть из каталога, остаток не меняется
- **Обнулить и архивировать** — списать оставшийся остаток и скрыть

**Логирование операций:**
- Списание → лист "Списание"
- Корректировка (+) → лист "Внесение"
- Корректировка (-) → лист "Списание"
- Все операции записывают: дата, SKU, количество, причину, пользователя

#### 2.3.5 CRM (Управление клиентами)

**Листы в Google Sheets:**
- `Leads` - карточки клиентов
- `MetricsDaily` - дневная статистика

**Колонки Leads:**
| Колонка | Описание |
|---------|----------|
| user_id | Telegram ID |
| username | Имя пользователя |
| first_seen_at | Первый визит |
| last_seen_at | Последний визит |
| stage | Стадия воронки |
| orders_count | Количество заказов |
| lifetime_value | Сумма всех заказов |
| last_order_id | ID последнего заказа |
| consent_at | Дата согласия |
| consent_version | Версия согласия |
| phone | Телефон |
| tags | Теги (vip, problem, discount, etc.) |
| notes | Заметки |

**Воронка продаж (стадии):**
```
🆕 new (Новый)
    ↓
👀 engaged (Смотрел каталог)
    ↓
🛒 cart (Добавил в корзину)
    ↓
📝 checkout (Оформляет заказ)
    ↓
✅ customer (Покупатель)
    ↓
🌟 repeat (Повторный)
```

**Функции CRM:**
- 📈 Воронка - статистика по стадиям
- 👥 Последние лиды - список клиентов
- 🔍 Поиск клиента - по ID/телефону/имени
- 📋 Отчёт за день - сводка
- 📝 Заметки к карточке клиента
- 🏷 Теги клиента
- 📜 История сообщений (при наличии согласия)
- 🧠 AI-сводка (при наличии OpenAI API key)

#### 2.3.4 Статус системы

Проверяет подключения:
- Google Sheets (таблица, листы, колонки)
- Google Drive (папка для фото)

Команды:
- `/health` - быстрая проверка (OK/DEGRADED)
- `/cleanup` - очистка временных файлов

## 3. Shop Bot (@mahoorka_bot)

**Путь:** `/app/`
**Назначение:** Каталог товаров, корзина, оформление заказов для покупателей

### 3.1 Главное меню

**Persistent меню (внизу):**
```
+------------------+------------------+
| 🗂 Каталог       | 🧺 Корзина       |
+------------------+------------------+
|            📋 Меню                  |
+-------------------------------------+
```

**Inline меню:**
- 🗂 Каталог
- 📋 Категории
- 🔍 Поиск
- 🧺 Корзина
- 📌 Условия
- 🤖 AI Менеджер

### 3.2 Роли и сущности

- **Покупатель** (Telegram-клиент): просмотр, корзина, заказ
- **Товар**: `sku`, `name`, `price_rub`, `stock`, `tags`, `photo_url`, `desc_short`
- **Корзина**: список `(sku, qty)` по `user_id`
- **Заказ**: итог корзины + телефон + доставка + PDF-счёт

### 3.3 Каталог товаров

**Отображение:**
- **Сетка 6 товаров (2×3)** на одной странице — `catalog_grid_kb()`
- Пагинация между страницами сетки
- Кнопки: "🛒 В корзину" для каждого товара
- Только inline-меню (убрана двойная навигация)

**Фильтрация:**
- Только активные товары (`Активен = TRUE`)
- Только с положительной ценой
- Только с положительным остатком

**Категории:**
- Строятся автоматически из тегов товаров
- Теги разделяются запятой в колонке `Теги`

### 3.4 Поиск

**FSM состояния:** `SearchState.query`

**Критерии поиска:**
- Название (contains, case-insensitive)
- Теги
- SKU (exact match)
- Краткое описание

### 3.5 Корзина

**Бизнес-правила добавления:**
1. SKU должен существовать
2. Остаток > 0
3. Нельзя превысить остаток (учитывается уже добавленное)
4. **Лимит: максимум 20 позиций** в корзине

**Управление:**
- `+` / `-` - изменение количества
- 🗑 - удаление позиции
- 🧹 Очистить - очистка корзины

**Отображение:**
- Список позиций с ценами и суммами
- Итоговая сумма
- Предупреждение о минимальной сумме (из настроек)
- **Счётчик на кнопке:** "🧺 Корзина (3)" — функции `get_cart_count()`, `get_cart_items_count()`

### 3.6 Оформление заказа (Checkout FSM)

**Состояния:** `CheckoutState`
- `phone` - ввод телефона
- `city_input` - ввод города (CDEK)
- `city_select` - выбор города
- `pvz_select` - выбор ПВЗ
- `delivery_manual` - ручной ввод доставки
- `confirm` - подтверждение заказа

**Сценарий:**
1. Проверка корзины (не пустая, >= минимальной суммы)
2. Ввод телефона (формат +7...)
3. Выбор доставки:
   - **CDEK** (если настроен): город → ПВЗ
   - **Ручной ввод**: текстовое описание
4. **Экран подтверждения заказа** — `order_confirm_kb()`:
   - Сводка: товары, сумма, доставка
   - Кнопки: "✅ Подтвердить заказ" / "❌ Отменить"
5. Финализация:
   - Генерация PDF-счёта
   - Запись в лист "Заказы"
   - Списание со склада (если включено)
   - Обновление CRM (lead stage → customer/repeat)
   - Очистка корзины
   - **Сообщение "Спасибо за заказ!"**

**Идемпотентность:**
- Заказ привязан к хэшу корзины
- Повторное оформление использует существующий `order_id`

### 3.7 AI-менеджер

**Активация:** выключен по умолчанию (пользователь включает вручную)

**Функции (tool calling):**
- `list_all_products` - список товаров
- `search_products` - поиск
- `add_to_cart` - добавление в корзину
- `show_cart` - показ корзины
- `checkout_hint` - подсказка по оформлению

**История:** последние 20 сообщений в SQLite

### 3.8 CRM-интеграция

Shop Bot автоматически обновляет CRM:

| Событие | Действие |
|---------|----------|
| /start | Создание lead (stage: new) |
| Просмотр каталога | stage → engaged |
| Добавление в корзину | stage → cart |
| Начало оформления | stage → checkout |
| Завершение заказа | stage → customer/repeat |

### 4.3 Загрузка данных

**Источник:** Google Apps Script (публикует данные из Google Sheets)

**Переменная окружения:** `VITE_APPS_SCRIPT_URL`

**Формат ответа:**
```typescript

  sku: string;

  descriptionShort: string;
  descriptionFull: string;

  stock: number;
```

## 9. Кеширование

| Компонент | Что кешируется | TTL |
|-----------|----------------|-----|
| Shop Bot | Каталог, настройки, категории | 60 сек |
| Website | Каталог (sessionStorage) | 5 мин |
| Owner Bot | Список товаров (ProductService) | 5 мин |
| Owner Bot | Column mapping | до перезапуска |

**Инвалидация:**
- Shop Bot: при списании со склада
- Website: при обновлении страницы после TTL
- Owner Bot (товары): автоматически при изменении товара, либо по TTL
- Owner Bot (columns): при перезапуске бота

## 10. Обработка ошибок

### 10.1 Глобальные обработчики

Оба бота используют глобальный error handler:
- Логирование с контекстом
- Пользователю показывается понятное сообщение
- Рекомендация начать заново (/start)

### 10.2 Retry-логика

**Google Sheets API:**
- Retry на ошибки 429, 500, 503
- Exponential backoff (1s, 2s, 4s)
- Максимум 3 попытки

### 10.3 Graceful degradation

| Сервис | При недоступности |
|--------|-------------------|
| OpenAI | AI отключается, используйте кнопки |
| CDEK | Ручной ввод доставки |
| Google Drive | Предупреждение, фото не загружается |
| Google Sheets | Критическая ошибка, повтор позже |
