# План портирования бота в мессенджер MAX

**Дата:** 26.02.2026
**Статус:** Планирование
**Оценка:** 3-5 дней разработки

---

## 1. Предпосылки

MAX — российский мессенджер от VK. Данные хранятся в РФ.
Запросы на миграцию ботов из Telegram в MAX выросли в 4-5 раз.
Клиент (ООО "ТОПХИТ") является юрлицом РФ — обязательное требование MAX.

---

## 2. Требования

### От клиента
- Верифицированное юрлицо РФ (ООО "ТОПХИТ" — есть)
- Аккаунт организации в MAX
- Создать бота через Master Bot в MAX, получить токен

### Технические
- Python 3.11+ (есть)
- Библиотека `maxapi` (pip install maxapi)
- Сервер с доступом к platform-api.max.ru

---

## 3. Что переиспользуется без изменений

| Модуль | Файлы | Причина |
|--------|-------|---------|
| Google Sheets клиент | `app/sheets.py` | Не зависит от мессенджера |
| Корзина | `app/cart_store.py` | SQLite, нет привязки к Telegram |
| CRM | `app/storage/crm.py` | SQLite, нет привязки |
| CDEK доставка | `app/cdek.py` | HTTP-клиент, не зависит |
| AI-менеджер | `app/ai_manager.py` | OpenAI API, не зависит |
| Бизнес-логика сервисов | `app/services/` | Чистая логика |
| Конфигурация | `app/config.py` | Pydantic, добавить MAX-токен |
| Docker | `Dockerfile`, `docker-compose.yml` | Минимальные изменения |

**Итого:** ~60% кода переиспользуется as-is.

## 4. Что нужно адаптировать

### 4.1 Транспортный слой (1 день)

**Файл:** `app/main.py`

Текущий код (aiogram):
```python
from aiogram import Bot, Dispatcher
bot = Bot(token=config.TELEGRAM_BOT_TOKEN)
dp = Dispatcher()
dp.start_polling(bot)
```

MAX-версия (maxapi):
```python
from maxapi import Bot, Dispatcher
bot = Bot(token=config.MAX_BOT_TOKEN)
dp = Dispatcher()
dp.start_polling(bot)
```

Изменения минимальны — API очень похож.

### 4.2 Хэндлеры (1-2 дня)

**Файлы:** `app/handlers/*.py`

| Хэндлер | Объём изменений | Примечание |
|---------|----------------|------------|
| `start.py` | Средний | Команда /start, приветствие |
| `common.py` | Средний | Общие обработчики |
| `navigation.py` | Большой | Inline-кнопки, callback_query |
| `ai.py` | Малый | Текстовые сообщения |

Основные отличия:
- `CallbackQuery` → `Callback` (другое имя класса)
- `InlineKeyboardMarkup` → аналог в maxapi
- `message.answer()` → `message.answer()` (совпадает)
- `callback_query.answer()` → адаптировать

### 4.3 Клавиатуры (1 день)

**Файл:** `app/keyboards.py` (создать `app/keyboards_max.py`)

MAX поддерживает:
- Inline-кнопки (аналог Telegram)
- Клавиатуры (reply keyboard)
- Callback data

Формат немного отличается — нужно адаптировать билдеры.

### 4.4 PDF-счета (0.5 дня)

**Файл:** `app/services/invoice.py`

Telegram отправляет документы через `send_document()`.
MAX имеет аналогичный метод — адаптировать вызов.

### 4.5 Deep links (0.5 дня)

**Файл:** `src/lib/catalog.ts` (сайт)

Текущий формат: `https://t.me/mahoorka_bot?start=sku_XXX`
MAX формат: другой URL-формат для deep links.

Решение: на сайте определять платформу пользователя и давать нужную ссылку.

## 5. Архитектура решения

### Вариант A: Отдельный бот (рекомендуется)

```
app/                    # Общая бизнес-логика
├── services/           # Корзина, заказы, скидки
├── sheets.py           # Google Sheets
├── cdek.py             # Доставка
│
app_telegram/           # Telegram-специфичный код
├── main.py
├── handlers/
├── keyboards.py
│
app_max/                # MAX-специфичный код
├── main.py
├── handlers/
├── keyboards.py
```

Преимущества:
- Независимые деплои
- Разные токены и конфиги
- Общая бизнес-логика через импорты

### Вариант B: Единый бот с абстракцией

Общий интерфейс `MessengerAdapter`, реализации для Telegram и MAX.
Сложнее в разработке, но единая кодовая база.

**Рекомендация:** Вариант A — проще, надёжнее, быстрее.

## 7. Риски

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| API MAX отличается больше, чем ожидалось | Средняя | Заложен буфер в оценке |
| Нет поддержки какой-то фичи в MAX | Низкая | Graceful degradation |
| Верификация юрлица занимает время | Средняя | Начать заранее |
| MAX меняет API | Низкая | Использовать офиц. библиотеку |
