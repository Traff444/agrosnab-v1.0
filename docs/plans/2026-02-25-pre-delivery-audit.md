## 1. Что сделано

### Shop Bot (@agrosna1b_bot)
Клиентский Telegram-бот для оформления заказов:

- Каталог товаров с поиском и бейджами (#hit, #sale, #new)
- Корзина (до 20 позиций, минимальная сумма заказа)
- Checkout с валидацией телефона и подтверждением заказа
- PDF-счета с поддержкой кириллицы (ReportLab)
- Интеграция со СДЭК (выбор ПВЗ, демо-режим)
- AI-менеджер на GPT-4o (опционально, выключен по умолчанию)
- Авто-списание со склада при оформлении заказа
- Deep links с сайта (переход в бот с конкретным товаром)

### Owner Bot (@tophitboss_bot)
Административный бот для управления складом:

- Приход товара (быстрый формат: "Название Цена Количество")
- Складские операции: списание, корректировка, архивирование
- Управление фото: анализ качества, авто-улучшение, загрузка в облако
- Поиск товаров по артикулу/названию
- CRM: воронка продаж (6 стадий), заметки, теги, отчёты
- Health-проверки подключений к Google Sheets и Drive
- Whitelist-безопасность (только разрешённые Telegram ID)

### Сайт (React/Vite)
Лендинг с каталогом товаров:

- Каталог из Google Apps Script
- Адаптивный дизайн (мобильный, планшет, десктоп)
- Кэширование данных (5 минут)
- Deep links в Telegram-бот

### Инфраструктура
- Docker + docker-compose для деплоя
- GitHub Actions (линтинг + тесты + деплой)
- Google Sheets как основная база данных
- Google Drive / Cloudinary для хранения фото

## 2. Архитектура

```
Пользователь → Сайт (React) → Deep link → Shop Bot (aiogram)
                                              ↓
                                        Google Sheets
                                              ↑
                              Owner Bot (aiogram) → Google Drive
```

| Компонент | Технология |
|-----------|-----------|
| Боты | Python 3.11, aiogram 3.6, Pydantic 2 |
| БД | Google Sheets API v4, SQLite (кэш) |

| Доставка | CDEK API v2 |
| AI | OpenAI GPT-4o (опционально) |
| CI/CD | GitHub Actions |
| Контейнеры | Docker |

## 3. Что работает хорошо

- **Модульная архитектура** — чёткое разделение: хендлеры → сервисы → хранилище
- **Типизация** — полные type hints с Pydantic-моделями
- **Обработка ошибок** — retry с экспоненциальным backoff для Google Sheets API
- **Безопасность** — whitelist-мидлварь, подтверждение опасных операций (TTL 5 мин)
- **Валидация** — Pydantic для конфигурации, валидация телефонов, экранирование HTML
- **Документация** — 15+ файлов документации, покрывающих бизнес-логику, API, деплой

## 4. Рекомендации

### 4.1 Безопасность

#### Ротация токенов (ВАЖНО)

Токены ботов следует ротировать перед production-использованием:

1. Откройте @BotFather в Telegram
2. Выберите бота → API Token → Revoke current token
3. Скопируйте новый токен в `.env`
4. Перезапустите бот

**Касается обоих ботов:** Shop Bot и Owner Bot.

#### Хранение секретов

Все секреты хранятся в `.env` (не в git). Рекомендации:
- Никогда не коммитить `.env` в репозиторий
- Для CI/CD использовать GitHub Secrets
- Для Docker — монтировать `/run/secrets` (уже настроено)

### 4.2 Тестирование

**Текущее покрытие:** ~40%

Протестировано:
- Корзина, сервисы, CDEK, счета, клавиатуры
- Безопасность (whitelist, подтверждения)
- Складские операции (списание, корректировка, архив)
- Парсер прихода товара, генерация SKU
- Анализ и улучшение фото

Не протестировано:
- Хендлеры ботов (start, catalog, cart, checkout)
- CRM-хендлеры
- AI-менеджер (интеграция)
- E2E сценарий полного заказа

**Рекомендация:** довести покрытие до 60%+ добавлением тестов хендлеров.

### 4.3 Мониторинг

- Sentry SDK подключен к Owner Bot (опционально)
- **Рекомендация:** включить Sentry для обоих ботов
- **Рекомендация:** настроить уведомления об ошибках в Telegram

### 4.4 Масштабирование

Текущий режим — polling (один экземпляр бота). Это подходит для MVP.
Для масштабирования в будущем:
- Миграция на webhooks (nginx reverse proxy)
- Замена SQLite на PostgreSQL
- Health check endpoint для мониторинга

### 4.5 Аналитика (сайт)

- Нет Google Analytics / Яндекс.Метрики
- Нет schema markup (JSON-LD)
- Нет sitemap.xml / robots.txt

**Рекомендация:** добавить аналитику для отслеживания конверсий.

### 4.6 Оплата

Сейчас оплата через PDF-счёт (ручной процесс).
**Возможное улучшение:** интеграция с ЮKassa или Тинькофф для онлайн-оплаты.
